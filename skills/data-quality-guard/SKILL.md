# 数据质量守卫：根因分析

> ⛔ **用户铁律**：「你修复BUG都是结果，要深层次的分析原因，以后不要再犯！」
> 
> **不要擦地，要堵水管。** DELETE 语句是擦地——下次还会脏。追溯数据从哪条管道进来的、在最早节点拦截——才是修水管。

## 你为什么反复清理垃圾？

因为每次都只修症状（DELETE 语句删数据），不堵源头（爬虫/适配器/评分引擎的缺陷）。

## 垃圾数据三大管道

```
管道1: batch_crawler.py (泛爬虫) — 70% 的垃圾来源
  缺陷: 对87站全量HTTP探测 → 抓取每个站 → 提取文本 → 评分入库
  根因: 没有判断页面是「公告详情」还是「平台首页/列表页」
  产物: "数智云采-框架协议采购 首页 >公告信息..."
        "交易信息 - 连云港市公共资源交易平台 首页 > 交易信息..."
        "天工招采平台 搜 索 返回天工开物 > 网站首页..."

管道2: dedicated_adapters.py → crawl_nanwang() — 20%
  缺陷: 从列表页提取 <a href="/zbgg/123.jhtml"> → 直接 fetch → 提取文本
  根因: 没有验证返回的HTML确实是公告详情（有些链接返回空页/重定向/面包屑页）
  产物: "招标公告-中国南方电网-供应链统一服务平台 您现在正在浏览：首页 >..."

管道3: 评分引擎 DIGITAL_GATE 泛化 — 10%
  缺陷: 关键词含"系统""服务""技术"等过于宽泛的词
  根因: 任何页面正文都能命中（锅炉改造正文有"系统"，洗衣服务正文有"服务"）
  产物: 锅炉增容改造=100分，员工工装洗涤=65分
```

## 三层拦截架构（已实现）

### L1: 入库前置 — `insert_notice()` 页面类型判别器

已实现在 `crawl_pipeline.py` 第85行，`insert_notice()` 函数入口处：

```python
# ── L1 页面类型判别器：拦截平台首页/导航页/列表页 ──
PLATFORM_SIGNALS = [
    '您现在正在浏览', '首页 >', 'APP下载', '关于我们',
    '返回首页', '平台首页', '设为首页', '收藏此页',
    '欢迎来到', '您好！欢迎', '框架协议采购 首页',
    '公告信息 公告信息', '交易信息 -',
    '电子保函综合服务平台', '搜 索 返回天工开物',
]
if any(sig in check_text for sig in PLATFORM_SIGNALS):
    return False  # 平台页，静默丢弃
```

**设计原则**：L1 在评分之前执行。平台首页根本不需要评分——直接用信号词拦截。

### L2: 评分引擎 — `NON_DIGITAL_EXCLUDE`

实现在 `relevance_scorer.py` 第285行。锅炉/煤矿/脱硫/洗衣等非数字化项目直接拒掉，除非同时命中数字化强关键词（智慧工地/BIM/数字孪生等）。

### L3: 中标独立评分

实现在 `relevance_scorer.py` 第315行。三逻辑：
1. 竞品中标（南网数字/华工精卓/南瑞等20家）→ 正常基础分25
2. 非竞品但含数字化关键词（管理平台/监控系统/APP/BIM）→ 降基础分15
3. 非竞品且无数字化关键词 → 直接丢弃

> 完整代码见 `references/layer-implementations.md`

## 验证清单

每次采集后检查：
- [ ] 中标表是否有 title 含"首页"、"您现在正在浏览" → L1 失效
- [ ] 招标表是否有平台首页特征 → L1 失效
- [ ] 中标表是否有锅炉/煤矿/洗衣 → L2 失效
- [ ] 中标是否有非竞品公司的无关中标 → L3 失效
