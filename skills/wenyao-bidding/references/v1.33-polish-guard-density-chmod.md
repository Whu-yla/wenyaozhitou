# V1.33 Polish Guard Token + Density 重犯防护

## 1. polish ENHANCE_CSS 守卫标识选择铁律

**致命坑**：`polish_report.py` 中用 `if 'TOKEN' not in html` 做 ENHANCE_CSS 的注入守卫。如果 TOKEN 是某个可能被回滚的功能的 CSS 类名，一旦该功能被移除，守卫永远为真 → **每次 polish 都重复注入**整段 CSS。

**案例 (2026-06-26)**：
- 守卫用 `'more-filters-toggle'` 检查是否已注入 ENHANCE_CSS
- 「更多筛选」功能被用户否决 → more-filters-toggle CSS 被回滚删除
- 守卫永远为真 → 每次 polish 注入一份新的 `@media(max-width:768px)` 块
- 结果：4 个重复的 `@media` 块 → 手机端布局全崩

**修复**：改用 `'hover-preview-tip'`（V1.33 引入的永久特性，不会被回滚）。

**铁律**：守卫标识必须满足两个条件：
1. 是 ENHANCE_CSS 自身包含的 CSS 类名
2. 该特性不会被回滚（或回滚时同步换守卫标识）

**验证**：连跑两次 polish，第二次必须输出「已抛光，跳过」。

## 2. 密度模式移动端豁免

**致命坑**：`localStorage.getItem('density') === 'dense'` 时 JS 自动给 body 加 `dense` class，但手机上桌面端的 `body.dense td{padding:4px;font-size:11px}` 会把卡片 Grid 布局压扁。

**双保险修复**：
- **JS 层**：`if (window.innerWidth > 768 && localStorage.getItem('density') === 'dense')`
- **CSS 安全网**：`@media(max-width:768px)` 内覆盖 `body.dense tr.data-row{padding:18px 16px!important}` 等

## 3. chmod 644 * 目录陷阱（polish v6 修复）

**致命坑**：`chmod 644 /var/www/html/bidding/*` — glob 命中 `img/`、`img_gen/` 目录 → 抹掉执行位(x) → `drw-r--r--` → nginx 无法 stat() 目录内文件 → logo/favicon/og-share 全部 403。

**polish v6 修复**：
```python
# 只 chmod 文件，不碰目录
for f in Path("/var/www/html/bidding").glob("*"):
    if f.is_file():
        f.chmod(0o644)
# 目录单独保 755
for d in ["/var/www/html/bidding/img", "/var/www/html/bidding/img_gen"]:
    subprocess.run(["chmod", "755", d])
```

## 4. polish html.replace 必须精确

**致命坑**：`html.replace('overflow:hidden', 'overflow:visible')` 同时命中桌面端（`flex:1;min-width:0;overflow:hidden`）和手机端（`position:relative;overflow:hidden`）→ 手机端滚动失效。

**修复**：用完整上下文 `html.replace('.filter-scroll-wrapper{flex:1;min-width:0;overflow:hidden}', ...)`。
