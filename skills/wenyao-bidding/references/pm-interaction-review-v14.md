# PM交互审查 — V1.14 案例研究

## 背景

V1.13 新增了独立的「收藏」Tab，V1.14 进行产品经理级全量交互审查。核心问题：
用户点出「现在有了单独的收藏TAB，那之前那个只看收藏的按钮就没有意义了」→ 要求全面审视。

## 发现的7个交互问题及修复

### 1. P0: 冗余交互入口

**问题**：筛选栏 `⭐ 收藏` 按钮 + 收藏Tab = 两个入口做同一件事。
**影响**：用户认知负担——"这两个收藏有什么区别？"
**修复**：删除模板中的 `<button id="btnStar" onclick="swStar()">⭐ 收藏</button>`

### 2. P0: 死代码残留

**问题**：删按钮但 `swStar()` 函数 + `resetF()` 中的 `btnStar` 引用未清理。
**影响**：控制台 `btnStar is null` 报错。
**修复**：完整删除 `swStar()` 函数定义 + `resetF()` 中的 `document.getElementById("btnStar")` 引用。

### 3. P1: Tab切换勾选污染

**问题**：在招标Tab勾选3条 → 切到收藏Tab → 那3条的checkbox还是勾着的。
**影响**：用户困惑——"我没在收藏Tab勾啊，怎么已经选上了？"
**修复**：`sw(t)` 函数第一行加 `selectedIds.clear()`

### 4. P1: starOnly 残留

**问题**：在收藏Tab看了一会儿 → 切回招标Tab → 结果招标Tab也显示收藏模式（starOnly=true 没重置）。
**影响**：招标Tab只显示收藏项，用户以为数据丢了。
**修复**：`sw(t)` 中 `else { starOnly = false; }` — 离开收藏Tab就关。

### 5. P2: 空状态空白页

**问题**：收藏Tab 0条 → 空白表格。搜索无结果 → 空白表格。
**影响**：用户以为页面坏了/加载失败。
**修复**：
- 收藏Tab空状态：`"⭐ 暂无收藏，在招标列表中点击 ☆ 即可收藏"`（引导用户下一步操作）
- 搜索空状态：`"🔍 没有匹配的结果，请调整筛选条件"`（告知原因+解决路径）

### 6. P3: 统计卡片破坏上下文

**问题**：在收藏Tab点"今日新增"统计卡片 → 强制跳回招标Tab。
**影响**：打断用户的收藏浏览上下文。
**修复**：`statClick()` 改为仅在趋势/竞品Tab时跳转，其他Tab保持当前位置 `doFilter()`。

### 7. 代码层面：resetF 死引用

**问题**：`resetF()` 中 `document.getElementById("btnStar")?.classList.remove("primary")`。
**影响**：按钮已删，此处返回null，控制台报错。
**修复**：清理引用，同时加 `selectedIds.clear()`。

## PM审查原则总结

| 原则 | 检查点 |
|:--|:--|
| 新功能上线 → 旧入口必删 | Tab替代了filter按钮？→ 删按钮 + 删函数 + 删引用 |
| 状态清理 | Tab切换时 `selectedIds` / `starOnly` / `pg` / `sf` 是否全部重置？ |
| 空状态设计 | 0条数据时显示引导文字，不是空白页 |
| 上下文保持 | 用户在当前Tab的操作不强制跳转其他Tab |
| 完整删除 | 删HTML元素 → 同时删JS函数 + DOM引用 + CSS类 |

- V1.14: PM全量审查（冗余清理、状态管理、空状态、上下文保持）
