序

2026年6月19日，一个 Python 脚本、一张 SQLite 表、一份 344 站 Excel 清单。
6月26日，一个拥有三层评分引擎、自愈守护、企微推送、AI 对话、手机端卡片化交互的智能投标监控系统。

这不是一份技术文档。这是一台系统学会「自愈」「精准」「诚实」的过程。每一个版本号背后，都是一次决策、一次失败、一次顿悟。

Ⅰ

七个进化阶段

阶段一 6/19–20 · V0.1–V0.2 地基
爬虫引擎 bidding_engine.py 搭建。SQLite 建表。344 站全量入库。三级关键词评分引擎 v1 诞生。
第一条铁律：「数智科技 ≠ EPC，只关注数字化/软件/AI 类招标」。
这个决定定义了此后 38 个版本的边界——过滤掉的东西，决定了你是谁。
阶段二 6/20–22 · V0.3–V0.6 交付
HTML 交互报告。Nginx 上线。企微推送。通义万相 AI 封面生成。客户分类引擎。
系统第一次从「脚本」变成「产品」——不是只在服务器里跑，而是推送到企业微信群、呈现在浏览器里、手机上能看。
一夕之间，从工具变成了信息中枢。
阶段三 6/22–23 · V0.7–V0.9 记忆与审美
🌓 明暗主题一键切换。长记忆系统上线——通义千问 Text-Embedding-V3 向量化 + HOT/WARM/COLD 三层架构。
SVG 趋势图。多选筛选器。客户/地域标签。
系统开始「记住」——不只是数据，还有用户偏好、交互状态、每一次反馈。
阶段四 6/23–24 · V1.0–V1.4 工业化
勾选批量导出。收藏 Tab。浙能适配器 41 条入库。国家能源 Chromium 渲染。中广核 API 反发现（/portalApi/content/queryPage）。
企微四连推：摘要 → 招标 TOP8 → 中标 TOP8 → 竞品分析。
从「我抓到了一些东西」到「我覆盖了六大发电集团」。
阶段五 6/24 · V1.5–V1.7 闭环
反馈自动修复机制上线：用户点踩 → 自动诊断根因 → 修代码 → 回填数据 → 重生成日报 → 主动报告。
AI 自然语言对话引擎。systemd 定时器迁移（Hermes Cron 3 分钟硬中断 → systemd 7200 秒超时）。
系统开始「自愈」——不是等有人来修，而是自己知道坏了、自己修、自己报。
阶段六 6/25 · V1.10–V1.19 精准化
评分引擎 v10→v12：信息安全/等保入闸 +25 基础分。三层拦截架构：L1 判别器 → L2 通用评分 → L3 中标独立评分。
NEW 标签语义三次迭代（fetch_date → publish_date → 归档差集）。dlzb Chromium 兜底 9 平台。
从「多抓」到「抓对」——宁可少十条，不混一条假的。
阶段七 6/25–26 · V1.20–V1.38 极致
手机端 Twitter 风格卡片重做。Nginx 3 秒自愈守护 + 企微秒级告警。蒙西直连。三桶油诚实放弃。
门户噪音防火墙。归档差集修复。搜索框无缝药丸。深圳能源修复——从 L1 全拒到鸿蒙智能楼宇 65 分入库。
系统的可信度，不是由它能做什么决定的，而是由它拒绝做什么决定的。
Ⅱ

每一次崩溃，都是一次架构升级

危机版本根因不是修 bug，而是——
Cron API 断连 V1.3 DeepSeek Broken pipe，定时采集全挂 → no_agent 纯 shell 管线，零 LLM 依赖，永不超时
全页白屏 V1.35 getElementById(null) → init 中断 → 0 条数据 → 四文件同步修复 + 幂等注入守卫，一个 null 不再能瘫痪整站
mkdocs 抢端口 V1.37 80 端口被占，nginx 反复启动失败 → Nginx 守护系统，每分钟检测 + 自动杀进程 + 重启，3 秒恢复 + 企微告警
全部标 NEW V1.37 归档从未写入，差集始终为空 → 归档自动写入 + 差集语义固化，今天 NEW = 昨天库里没有
门户噪音 70 分 V1.37 「欢迎来到 V1.0」含「招标」二字 → 三层拦截 + 黑名单防火墙，导航页即使含关键词也直接拒绝
深圳能源全拒 V1.38 索引页被当详情，10/10 L1 假阳性 → /index* 过滤 + .Content div 正文 + h1 标题清洁

「修 bug」和「升级架构」的区别

修 bug：把 mkdocs 进程杀了。升级架构：部署一套守护系统，让任何人、任何进程抢端口都不再是问题。
修 bug：把 is_new 字段改对。升级架构：把「新」的定义从日期字段改为归档差集，让语义对齐用户心智而非技术便利。

前者解决眼前。后者杜绝同类。

Ⅲ

三大产品原则

1

起点可以很简陋，进化必须很快

V0.1 只有一个 bidding_engine.py 和一张 SQLite 表。没有 UI，没有定时，没有推送。
7 天后，39 个版本：11 路适配器、三层评分、自愈守护、企微推送、AI 对话、手机端卡片。

不要等想清楚了再动手。V0.1 就上线，然后一天一个版本地迭代。
完美的第一版不存在。但持续进化的系统，可以很接近完美。

2

诚实 > 聪明

V1.37 三桶油探测：中石油验证码弹窗、中石化 ECS 网络不可达、中海油 193 字节 JS 空壳、ctbpsp 滑块验证码、dlzb 无相关板块。五条路径，全部确认不可达。
结论不是「再试试」，而是写入探测矩阵文档，诚实告诉用户：当前环境不可达。

V1.38 蒙西电网确诊：116 条 ID 全量扫描，0 件数字化项目。适配器代码没问题，但平台是纯电力设备采购。
结论是「评分为 0 是正确的」，不调低阈值强行放行。

知道什么做不了，和知道怎么做到一样重要。
宁可报告里少十个平台，不能有一条假数据混在里面。一条假阳性，比十条空缺更伤害信任。

3

语义对齐比技术实现难十倍

「今日新增」这个词，改了三次：
· V1.16：从 is_new 静态字段改为 fetch_date 实时判断
· V1.18：从 fetch_date 改为 publish_date（用户心智：今天发布 = 新）
· V1.37：从日期字段判断改为对比昨天归档做 ID 差集（用户心智：昨天库里没有、今天出现 = 新）

一个词的定义，三次迭代，才最终对齐用户心智。
技术实现只是 50%。另一半是把「用户觉得什么是合理的」变成系统行为。

Ⅳ

贯穿 39 个版本的三条暗线

暗线一 自愈
V1.2 Nginx 健康守护 → V1.3 no_agent 防 API 断连 → V1.7 systemd 防硬中断 → V1.37 3 秒自愈 + 企微告警。
这条线贯穿始终：系统必须比它的创建者更可靠。不是「有人看着所以能跑」，而是「没人看着也不会坏」。
暗线二 精准
V0.2 评分引擎 v1 → V0.5 EPC 噪音清零 → V1.11 三层拦截 → V1.37 门户防火墙。
过滤比抓取更重要。每一层拦截都是一个承诺：进来的数据，值得你看。
暗线三 诚实
V1.1 大唐/国网/华能确认不可达 → V1.37 三桶油五路全死 → V1.38 蒙西确诊。
不粉饰、不强求、不假装。探测矩阵里的每一条「不可达」记录，和每一条入库数据一样有价值。

不是代码写得多好，而是你不在的时候，它依然能替你做正确的决定。
